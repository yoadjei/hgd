# 1. CORE RESEARCH THESIS

The project investigates:

> **When a tool-using agent's long-horizon success falls below what its matched short-horizon competence predicts, how much of that shortfall is caused by self-conditioning on earlier errors, stale environment-state beliefs, and irrecoverable typed errors, as measured through counterfactual replay under a controlled horizon sweep?**

The central scientific contribution is:

> **An interventional decomposition of the horizon gap in long-horizon tool-using LLM agents.**

The project must determine whether the degradation observed in long-horizon execution can be decomposed into identifiable mechanism-specific components through controlled interventions.

The three principal mechanisms are:

1. **Self-conditioning**
   The agent conditions on its own earlier erroneous history.

2. **State staleness**
   The agent acts on a stale or incorrect belief about the environment state.

3. **Irrecoverability**
   A specific error causes downstream failure because the action or state transition becomes difficult or impossible to recover from.

The central empirical objects are:

* Horizon gap `Δ(s)`
* Positional hazard `h(u)`
* Survival function `S(u)`
* Recovery function `R(e,u)`
* Propagation probability/kernel `π(e,u)`
* Mechanism decomposition shares:

  * `θ_self`
  * `θ_state`
  * `θ_irrecov`
  * residual component where appropriate

Do not replace these objects with a new arbitrary composite metric.

# 7. REQUIRED CAUSAL FRAMEWORK

Use the stated agent loop:

`S_t -> A_t -> S_{t+1}`

with history `H_t`, environment state `S_t`, and policy:

`A_t = π(H_t)`

The principal interventions are:

### Intervention 1: History scrub

`do(H_t := H_t^clean)`

Keep the factual environment state fixed.

Interpretation:

> effect attributable to erroneous history or self-conditioning.

### Intervention 2: State refresh

Provide an oracle-derived state summary while preserving the factual history.

Interpretation:

> effect attributable to stale or incorrect state beliefs.

### Intervention 3: Oracle fix

Replace the erroneous action with a corrected action.

Interpretation:

> downstream propagation and irrecoverability of the specific error.

Every causal claim must state:

1. the intervention;
2. what is held fixed;
3. the estimand;
4. the identification assumption;
5. the outcome;
6. the uncertainty interval.

Never write "this proves X" when the intervention only identifies X under an untested assumption.

# 8. HORIZON GAP

Use the matched short-versus-long construction.

For atomic subtask success estimates:

`p̂_i`

define:

`P_ind(s) = Π p̂_i`

and:

`Δ(s) = log P_obs(s) − log P_ind(s)`

Interpretation:

* `Δ(s) ≈ 0`: observed degradation is compatible with independent errors.
* `Δ(s) < 0`: excess horizon degradation beyond the independent-error prediction.

The project is specifically interested in explaining this residual.

Do not redefine the horizon gap merely to obtain a stronger effect.

Do not select a formulation after observing which one produces significance.

Any alternative formulation must be pre-specified or explicitly labelled exploratory.

---

# 9. POSITIONAL HAZARD

Define normalised trajectory position:

`u = t / H*`

where `H*` is the intrinsic horizon constructed for the task family.

Primary descriptive quantity:

`h(u) = P(first unrecovered critical error at u | none before u)`

Use discrete-time competing-risk survival analysis.

Primary model:

* discrete-time hazard
* complementary log-log link
* mixed-effects structure
* task/scenario random effect
* spline or other pre-specified flexible representation for `u`

Do not introduce Cox regression merely because it is familiar.

Do not add complicated latent-state models unless justified by a specific methodological problem.

A change-point analysis is exploratory unless explicitly pre-registered as primary.

# 16. STATISTICAL RULES

Use the statistical plan in the audit unless a methodological issue requires an explicit amendment.

Primary tools:

### Survival

Discrete-time competing-risk hazard model.

### Horizon gap

Paired bootstrap over matched scenarios.

### Replay effects

Mixed-effects logistic model.

Report effects as risk differences with 95% confidence intervals where appropriate.

### Mechanism shares

Estimate:

`θ_k = (Δ_before − Δ_after,k) / Δ`

with uncertainty intervals.

Because sequential intervention decomposition can be order-dependent:

* report sequential-order sensitivity;
* use a full factorial design where feasible;
* use Shapley decomposition if the full intervention combination is available.

Multiplicity:

Use Holm correction across pre-registered primary tests.

Everything else is exploratory unless explicitly pre-registered.

Do not add statistical tests merely because they are available.

Do not p-hack.

Do not selectively report favourable models, seeds, tasks, or intervention branches.

# 17. EXPECTED RESULTS ARE NOT FACTS

The audit contains hypotheses.

Treat every expected result as a hypothesis.

Particularly:

* self-conditioning may explain a substantial fraction of the gap;
* the effect may shrink with model scale;
* reasoning may reduce self-conditioning;
* certain state-changing actions may have high propagation probability;
* some supposed "forgetting" errors may actually be self-conditioning.

These are not conclusions.

Never write or reason as though they have already been demonstrated.

The project must remain valid if:

* self-conditioning is weak;
* staleness dominates;
* irrecoverability dominates;
* the mechanisms interact;
* the decomposition shares are unstable;
* the horizon gap is small;
* taxonomic labels do not map cleanly onto interventions.

# 18. KILL CONDITIONS

The following conditions must trigger an explicit research decision.

### Kill condition A

`Δ(s)` is not distinguishable from zero.

Interpretation:

The primary phenomenon may be explained by independent errors.

Do not exaggerate a null result.

Pivot as specified by the audit.

### Kill condition B

All intervention effects are small and confidence intervals materially include zero.

Interpretation:

The proposed mechanisms are not sufficiently identified.

Pivot towards positional hazard modelling or another explicitly scoped alternative.

### Kill condition C

Replay is not reproducible.

Do not claim causal inference from unreliable replay.

Fix the infrastructure or change benchmark.

### Kill condition D

Judge agreement is poor.

Restrict the analysis rather than lowering standards.

### Kill condition E

Novelty is shown to be substantially duplicated.

Do not publish a superficially renamed replication as a novel contribution.

Reformulate or abandon the claim.

# 19. REVIEWER ATTACKS TO ANTICIPATE

At every stage, actively test the project against these objections:

### "This is just HORIZON."

Answer through the intervention-based causal decomposition.

### "This is just Sinha with tools."

Demonstrate a mechanism result that requires environment state and recovery dynamics.

### "This is just survival analysis."

Make clear that survival analysis is the descriptive layer and the contribution is mechanism-specific intervention shares.

### "Your taxonomy is subjective."

Rely primarily on deterministic rules and state checks; validate the residual judged categories.

### "Your causal effect is really an artefact of the intervention."

Test placebo controls and intervention-specific identification assumptions.

### "The oracle summary changes the model beyond state knowledge."

Add a placebo-summary control and discuss the identification limitation.

### "The decomposition is order-dependent."

Use factorial or Shapley analysis where feasible and report order sensitivity.

### "Task difficulty explains the degradation."

Use matched atomic and composed subtasks.

### "Your benchmark is too easy."

Use a secondary ecological-validity environment and discuss scope carefully.

### "You only studied one agent architecture."

Scope claims to the tested ReAct-class setup unless the experiments justify broader generalisation.

### "This is merely correlation."

Keep observational analyses separate from intervention-based causal estimates.

### "Your surprising result was predicted by prior literature."

Search for the prediction before claiming novelty.

# 35. FINAL SUCCESS CONDITION

The project succeeds scientifically only if it can establish, with defensible uncertainty estimates, something that descriptive long-horizon studies could not establish.

The ideal result is not:

> "Long tasks fail more."

It is not:

> "Failure rates increase with horizon."

It is not:

> "Agents have different reliability profiles."

The target result is of the form:

> **A measurable proportion of the excess horizon degradation is attributable to specific intervention-defined mechanisms, with their contributions varying by position, error type, model condition, or state-changing context.**

The strongest possible finding would be a non-obvious mechanistic result that cannot be obtained from failure labels or success curves alone.

The project should particularly test, rather than assume, whether some behaviours labelled as "catastrophic forgetting" are better explained as self-conditioning on an earlier erroneous trajectory even when the relevant constraint remains available in context.

That is a hypothesis, not a predetermined conclusion.
